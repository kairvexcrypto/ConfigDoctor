# ConfigDoctor

Проверка YAML-конфигураций для Paper 1.21.11 и Java 21. Проект Warndev.

ConfigDoctor читает файлы из папки `plugins` и сопоставляет их с правилами администратора. Он находит пропущенные поля, неверные типы, выход за диапазоны и нарушения структуры. Исходные конфигурации не изменяются.

Версия 0.1.0. Сборка и 56 автоматических тестов прошли. Запуск на игровом сервере пока не проверен; сценарий приёмки находится в [ACCEPTANCE.md](ACCEPTANCE.md).

## Установка

1. Соберите проект: `mvn clean verify` на JDK 21 и Maven 3.9+.
2. Поместите `target/ConfigDoctor-0.1.0.jar` в `plugins` тестового Paper 1.21.11. Файл `original-ConfigDoctor-0.1.0.jar` не устанавливайте: в нём нет встроенного YAML-парсера.
3. Перезапустите сервер. Появятся `plugins/ConfigDoctor/rules.yml` и `example.yml`.
4. Выполните `/cdoc check example`, затем `/cdoc report`.
5. Добавьте правила для своих плагинов и выполните `/cdoc reload`.

SnakeYAML 2.4 включён в итоговый JAR с переносом пакетов, чтобы не подменять библиотеки сервера. Другие плагины для работы не требуются.

## Команды и доступ

| Команда | Назначение | Право |
|---|---|---|
| `/cdoc help` | Справка | `configdoctor.use` |
| `/cdoc profiles` | Список профилей | `configdoctor.use` |
| `/cdoc check <id>` | Проверить один файл | `configdoctor.check` |
| `/cdoc checkall` | Проверить все профили | `configdoctor.check` |
| `/cdoc report [страница]` | Последние результаты, 8 строк на страницу | `configdoctor.check` |
| `/cdoc reload` | Загрузить новую схему правил | `configdoctor.reload` |
| `/cdoc export` | Сохранить последний отчёт в Markdown | `configdoctor.export` |

Все права по умолчанию доступны операторам. Для любой команды дополнительно требуется `configdoctor.use`. Поддерживаются игроки и серверная консоль. Командные блоки не поддерживаются.

## Формат правил

```yaml
version: 1
profiles:
  arena:
    file: Arena/config.yml
    rules:
      - path: /enabled
        type: boolean
        required: true
      - path: /players/max
        type: integer
        min: 2
        max: 100
        required: true
      - path: /mode
        type: string
        allowed: [survival, arena]
      - path: /arena/world
        type: string
        required: true
        min-length: 1
        when:
          path: /mode
          equals: arena
      - path: /worlds
        type: array
        item-type: string
        unique: true
        max-items: 20
      - path: /database
        type: object
        allowed-keys: [host, port, user, password]
      - path: /messages/prefix
        type: string
        max-length: 64
        severity: warning
```

Путь поля записывается как JSON Pointer: `/players/max`, `/worlds/0`. Символ `/` внутри ключа кодируется как `~1`, символ `~` — как `~0`. Пустая строка обозначает весь документ. Индекс массива не должен содержать ведущие нули.

| Параметр | Семантика |
|---|---|
| `type` | `string`, `boolean`, `integer`, `number`, `array`, `object` |
| `required` | Ошибка, если поля нет; по умолчанию `false` |
| `nullable` | Разрешить YAML null; по умолчанию `false` |
| `min`, `max` | Включительные границы числового значения |
| `min-length`, `max-length` | Длина строки в Unicode code points |
| `min-items`, `max-items` | Границы количества элементов массива |
| `item-type` | Тип каждого элемента массива; null ему не соответствует |
| `unique` | Уникальность скалярных элементов; числа 1 и 1.0 равны |
| `allowed` | Непустой список разрешённых скалярных значений |
| `allowed-keys` | Полный список допустимых ключей объекта; отсутствие ключа само по себе не ошибка |
| `when` | Выполнить правило, только если указанное поле присутствует и равно `equals` |
| `severity` | `error` или `warning`; по умолчанию `error` |

Неизвестные параметры и несовместимые ограничения отклоняются при загрузке. При неудачном `/cdoc reload` действующая схема сохраняется. `nullable: true` разрешает null, но заданный `allowed` также должен его включать. `integer` принимает числовые значения без дробной части, включая `10.0`.

Парсер использует семантику YAML 1.1. Строки, похожие на даты, числа или булевы значения (`yes`, `no`, `on`, `off`), следует заключать в кавычки. Даты и произвольные объектные теги не поддерживаются. Дубликаты ключей, ссылки на коллекции и нестроковые ключи отклоняются.

## Выполнение и ограничения

Чтение файлов, разбор YAML, проверка и экспорт выполняются одним рабочим потоком. Очередь ограничена четырьмя ожидающими операциями. Проверка получает снимок правил в момент запроса; последующая перезагрузка не меняет уже поставленный запрос. Сообщения игрокам отправляются через главный поток Paper.

- До 32 профилей, 256 правил на профиль и 256 замечаний на файл. Усечённый отчёт явно помечается и не считается успешным.
- Файл до 1 МиБ, глубина до 32 уровней, до 50 000 узлов после разбора. Путь поля до 2048 символов.
- Допускаются относительные `.yml`/`.yaml` пути вида `Plugin/config.yml`. Абсолютные пути, `..` и обнаруженные символические ссылки запрещены.
- Результаты привязаны к отправителю, хранятся 10 минут, максимум для 32 отправителей. Выход игрока очищает его результаты.
- Экспорт находится в `plugins/ConfigDoctor/reports`. При 100 файлах новый экспорт отклоняется до ручного архивирования старых файлов.
- Отчёт содержит имена профилей, файлов, пути правил и коды нарушений. Сами значения конфигурации и фрагменты ошибочного YAML в отчёты и сообщения не включаются. Не помещайте секреты в имена профилей или пути правил.

Проверка не гарантирует работоспособность стороннего плагина: она проверяет только заданные правила и файлы на диске, а не настройки, уже загруженные другим плагином в память. Файл, изменившийся во время чтения по размеру, времени или идентификатору, отклоняется. Это не изоляция от другого процесса с правом одновременно менять каталог `plugins`; права файловой системы остаются ответственностью администратора.

ConfigDoctor не исправляет файлы, не выполняет команды из YAML и не перезагружает другие плагины. Поддержка Folia и других версий Paper не заявлена.
